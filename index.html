QNyx 3.0.2

A tunnel designed around the network you actually have.

Networks are not clean laboratory environments. Links disappear. Packets arrive late. Routes change. Satellite connections move. Wireless links degrade.

QNyx is built around a simple premise: the network underneath the tunnel is allowed to be imperfect.

QNyx provides an encrypted transport layer between endpoints while keeping the implementation small enough to run on commodity Linux edge hardware.

Deployment, command syntax, firewall requirements, and log-based troubleshooting are documented in the QNyx 3.0.2 Operator's Manual .

Security Model

Designed for data that has to remain protected.

QNyx approaches network security as a transport problem: establish authenticated post-quantum sessions, protect traffic, and continuously refresh session material while the tunnel remains operational.

  • KEM

    ML-KEM-1024 provides post-quantum key encapsulation for protected session establishment.

  • Authentication

    ML-DSA-65 provides post-quantum digital signatures within the QNyx cryptographic architecture.

  • Payload

    HF8 + AES-GCM protects tunnel traffic with authenticated encryption.

  • Rekeying

    Session material is automatically refreshed every 900 seconds.

  • Transport

    QNyx is designed to operate over ordinary IP connectivity, allowing the encrypted tunnel to sit above the physical network carrying the traffic.
